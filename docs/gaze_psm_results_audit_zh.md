## 3. 全任务位置结果：应该怎样下结论

正 lag 表示 gaze 领先，负 lag 表示 gaze 滞后。以下 CI 是按参与者 bootstrap 重新找峰后的 95% 区间，单位全部换算为 ms。

| 任务 | 器械 | 峰值 lag [95% CI] ms | 峰值 r | 零 lag 的 r | 峰值比零 lag 增加 | 判断 |
|---|---|---:|---:|---:|---:|---|
| A | L | +195 [-49, +317] | 0.195110 | 0.194262 | 0.000847 | 领先方向不确定 |
| A | R | +341 [+268, +439] | 0.489270 | 0.482461 | 0.006809 | 峰值分布支持位置轨迹领先 |
| C | L | +195 [-122, +488] | 0.484561 | 0.483885 | 0.000675 | 领先方向不确定 |
| C | R | -171 [-268, -146] | 0.518983 | 0.517165 | 0.001818 | 峰值分布支持位置轨迹滞后 |

四组均为 11 位稳定参与者，主峰未到搜索端点；1000 次 bootstrap 的端点比例均为 0。

## 4. 阶段结果与敏感性：不能只摘一个提前量

所有阶段完整数值见文末 80 组附表。`psm_stage` 为主阶段分析，允许 gaze 来自邻近阶段；`within_stage` 则只允许同一连续片段内配对。

### 4.1 主要阶段模式

| 条件 | 主阶段结果 | 同片段结果 | 应如何解释 |
|---|---|---|---|
| A transfer / L | +463 ms，CI [+98,+805] | 0 ms，CI [0,+122] | 主分析领先，明显依赖允许跨阶段配对 |
| A transfer / R | +683 ms，CI [+585,+829] | +49 ms，CI [0,+171] | 同样对阶段边界筛选敏感 |
| A place / R | -195 ms，CI [-488,-49] | -341 ms，CI [-488,-122] | 两种模式均呈负 lag，但不是完全相同的样本条件 |
| C reach string / R | +512 ms，CI [+146,+610] | +439 ms，CI [-98,+537] | 主分析领先；严格同片段下方向不再明确 |
| C wrap / L | +1610 ms，CI [-24,+1952] | 0 ms，CI [-123,0] | 不能只拿 +1.61 s 点估计当作稳定提前量 |
| C threading / L | +390 ms，CI [-2000,+537]，8 人 | -2000 ms，CI [-2000,+2000]，6 人 | 支持较少、区间宽、端点问题严重 |
| C pull/cinch / L | -2000 ms，端点 | -2000 ms，端点 | 不能报告真实延迟恰好 -2 s |
| C pull/cinch / R | +2000 ms，端点 | +171 ms，CI [0,+2000] | 主分析触边，同片段仍不精确 |

阶段差异与“提前观察下一步位置”的解释可以相容，但阶段筛选也改变了可用配对、记录和部分参与者集合，不能单凭两种模式的差异证明这个行为机制。

`drop ring` 对应 A 任务的 8 个组条件（左右 × position/velocity × 两种模式）均没有有效主组曲线；结果为空是明确的支持不足，不能记成 lag=0、r=0。C threading 的主阶段只有 8 人，同片段仅 6 人，不能套用全任务 11 人的稳定性。

### 4.2 当前最明显的端点问题

主阶段 C pull/cinch：L 的观察峰值为 -2 s，bootstrap 端点比例 **63.5%**；R 为 +2 s，端点比例 **69.2%**。即使 CI 全在零的一侧，仍不能把搜索边界当作精确时延。

同片段 C threading：L 和 R 的观察峰值都在 -2 s，端点比例分别 **53.3%**、**58.9%**。这类曲线应报告“当前窗口下无法得到可靠精确峰值时间”。若研究需要扩展 lag 搜索，应作为另外的敏感性分析保存，并检查长 lag 下的配对支持。

|---|---:|---:|---:|---:|
| A L grab / within_stage | 11 | -244 | -244 | 0.0191 |
| A L place / within_stage | 9 | -317 | -268 | 0.0171 |
| A R grab / within_stage | 11 | -293 | -293 | 0.0136 |
| C L threading / psm_stage | 8 | +390 | +439 | 0.0723 |
| C L threading / within_stage | 6 | -2000 | -2000 | 0.0431 |
| C R pull/cinch / within_stage | 11 | +171 | +195 | 0.0205 |

## 5. 空间对应是否支持“先看到同一点”

距离不是去均值后的距离；但使用的是传入计算的平滑后像素位置。组值是“记录中位距离先在人内平均，再在人间平均”。当前 50 px 半径只是探索性阈值。

| 任务 | 器械 | 零 lag 距离 px | 峰 lag 距离 px | 零 lag 50px 内 | 峰 lag 50px 内 |
|---|---|---:|---:|---:|---:|
| A | L | 493.00 | 491.72 | 1.30% | 1.32% |
| A | R | 293.53 | 290.56 | 3.92% | 3.99% |
| C | L | 188.44 | 188.48 | 7.57% | 7.63% |
| C | R | 153.16 | 152.92 | 12.39% | 12.48% |

将位置轨迹移到相关峰值 lag 后，空间距离改善也很小，C 左甚至略增。因此这些结果不能证明大量 gaze 与随后器械质心落在同一小区域。

较大距离可能来自 gaze 看着下一步目标而非器械质心、质心与尖端的偏差、坐标注册问题或其他因素。**本次证据不足以确定是哪一种原因，不能仅凭这些距离就断言坐标一定错误。**

若研究问题是“眼睛是否先到达器械随后到达的同一位置”，下一步最有价值的是在原视频上叠加 gaze、整体 mask 质心及尖端/目标，并分别验证坐标注册和目标定义，再做事件级到达分析。

## 6. 数据覆盖与速度结果需要保留的限制

84 条记录时长约 63.69～609.74 s。按原始相邻时间差中位数估计的帧率约 31.04～60.25 Hz，统一到 41 Hz；输出 lag 的网格分辨率约 24.39 ms，插值不会创造更高采集精度。

gaze 的网格有效比例最低约 **45.29%**；左器械最低约 **30.80%**；右器械最低约 **8.68%**（`User11_8_1`）。这些是单条记录的最低覆盖率，不是所有样本的缺失比例。提取状态 `ok` 只说明处理成功，不表示每条轨迹都有很高覆盖。

全任务速度峰值如下：

| 任务 | 器械 | lag [95% CI] ms | r |
|---|---|---:|---:|
| A | L | -220 [-244,+439] | 0.0327 |
| A | R | -220 [-244,-195] | 0.0460 |
| C | L | -220 [-244,-73] | 0.0226 |
| C | R | -195 [-220,-146] | 0.0325 |

速度相关仅约 0.02～0.05，部分位置正 lag 与速度负 lag 不一致。两种指标衡量的问题不同；还需要考虑差分对噪声、同步误差的敏感性，不能合并成一个统一的“眼手延迟”。

整任务位置曲线还可能受共同缓慢趋势、任务进程或相机运动影响。精确解析时间戳只解决数值读取问题，不能替代对采集设备固定时延和跨设备同步的实验校准。本次没有原始画面或同步校准证据，因而不把这些 lag 直接解释为纯粹的生理反应时间。
